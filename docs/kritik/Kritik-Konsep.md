## 3. KRITIK PRICING & PLAN

### Masalah 1: Tidak Ada Analisis Harga

Harga subscription (Rp9.900 / Rp29.000 / Rp299.000) disebut "misal" — tidak ada dasar mengapa angka itu yang dipilih.

Pertanyaan juri yang pasti muncul:
- "Kenapa Rp29.000 dan bukan Rp19.000 atau Rp49.000?"
- "Ada benchmark dari app sejenis?"

### Masalah 2: Tidak Ada Free-to-Paid Conversion Analysis

Dokumen asumsikan 30% conversion rate (download → paid). Angka ini sangat tidak realistis.

Data industri:
- App travel Indonesia: 3-8% conversion rate
- App subscription general: 2-5%
- Spotify (global): ~3%
- Duolingo (dengan gamifikasi kuat): ~5%

Dengan 5% conversion, semua angka revenue berubah drastis.

### Masalah 3: Weekly Pass Tidak Jelas Positioning-nya

```
Weekly Pass  = Rp9.900/minggu = Rp42.600/bulan (kalau renew 4x)
Monthly Pass = Rp29.000/bulan
```

Weekly LEBIH MAHAL dari Monthly kalau dihitung per bulan. Ini pricing yang membingungkan user. Siapa yang mau bayar Weekly kalau Monthly lebih murah?

### Masalah 4: Exclusive Pass Terlalu Jauh dari Monthly

```
Monthly   = Rp29.000/bulan = Rp348.000/tahun
Exclusive = Rp299.000/tahun = Rp24.917/bulan
```

Exclusive MALAH LEBIH MURAH dari Monthly kalau dihitung per bulan. User yang bayar Monthly selama setahun rugi Rp49.000 dibanding Exclusive.

### REKOMENDASI PRICING:

```
OPSI A (Sederhana, recommended untuk kompetisi):
├── Free: fitur dasar, 3 rekomendasi/hari, iklan
├── Premium Monthly: Rp19.900/bulan (lebih murah dari Netflix mobile)
├── Premium Yearly: Rp149.000/tahun (= Rp12.417/bulan, diskon 37%)
└── Hapus Weekly Pass (membingungkan, revenue kecil)

OPSI B (Freemium + Transaction):
├── Free: semua fitur browsing + matching
├── Transaction fee: 5% per booking open trip
├── Premium: Rp29.000/bulan = no fee + priority + exclusive deals
└── Model ini lebih sustainable karena revenue dari transaksi, bukan hanya subscription
```

## 6. KRITIK PERHITUNGAN FINANSIAL

### Error #1: Conversion Rate 30% (Seharusnya 5%)

```
Asumsi dokumen: 115.000 download → 34.500 paid (30%)
Realistis:      115.000 download → 5.750 paid (5%)
Dampak:         Revenue over-count 6x lipat
```

### Error #2: Retention 100% (Seharusnya 70%/bulan)

```
Asumsi dokumen: 34.500 subscriber × 12 bulan = 414.000 user-months
Realistis:      34.500 × (1-0.7^12)/(1-0.7) = 112.264 user-months
Dampak:         Monthly revenue over-count 3-4x
```

### Error #3: Weekly Pass Multiplier Salah

```
Dokumen: Weekly × 12 (weekly bayar 12x setahun?)
Seharusnya: Weekly × 52 (bayar per minggu = 52x/tahun)
```

### Error #4: Total "Sekali Purchase" Tidak Konsisten

```
Ditulis: Rp1.632.525.000
Cek manual: Rp1.000.500.000 + Rp1.031.550.000 + Rp170.775.000 + Rp30.000.000
          = Rp2.232.825.000
Selisih: Rp600.300.000 hilang tanpa penjelasan
```

### Error #5: IRR Tidak Dihitung

Panduan BMC minta IRR. Tidak ada perhitungannya.

### Error #6: Tidak Ada Break-Even Analysis

Berapa user minimum untuk balik modal? Tidak dihitung.

### Error #7: Download Target 115.000 Tahun Pertama = Tidak Realistis

App travel baru tanpa brand → 5.000-20.000 download realistis. 115.000 butuh budget marketing besar yang tidak dihitung.

### REKOMENDASI PERHITUNGAN:

```
Gunakan asumsi realistis:
├── Download tahun 1: 20.000 (bukan 115.000)
├── Conversion rate: 5% (bukan 30%)
├── Paid users: 1.000 (bukan 34.500)
├── Retention: 70%/bulan (bukan 100%)
├── Monthly pass: 50% dari paid = 500 user
├── Yearly pass: 30% dari paid = 300 user
└── Marketplace: 50 booking/bulan

Revenue realistis:
├── Monthly: 500 × Rp19.900 × 8 cycle = Rp79.600.000
├── Yearly: 300 × Rp149.000 = Rp44.700.000
├── Marketplace: 50 × Rp500.000 × 10% × 12 = Rp30.000.000
├── Partnership: 5 × Rp1.000.000 × 12 = Rp60.000.000
├── AdMob: ~Rp50.000.000 (estimasi konservatif)
└── Total: ~Rp264.300.000/tahun

Cost realistis (tim ramping):
├── Gaji 3 orang: Rp20.000.000/bulan = Rp240.000.000/tahun
├── Infrastruktur: Rp1.000.000/bulan = Rp12.000.000/tahun
├── Marketing: Rp5.000.000/bulan = Rp60.000.000/tahun
├── Lain-lain: Rp3.000.000/bulan = Rp36.000.000/tahun
└── Total: ~Rp348.000.000/tahun

Laba = Rp264.300.000 - Rp348.000.000 = -Rp83.700.000 (RUGI di tahun 1)
Break-even: bulan ke-16-18 (kalau growth 10%/bulan)
```

Angka ini lebih realistis dan lebih kredibel untuk juri daripada klaim Rp43 Miliar revenue.
